# Веб-сервис хранения и просмотра гистосканов

Сервис по техническому заданию [PRD.md](PRD.md): администратор загружает сканы (Aperio SVS и другие однофайловые форматы, которые читает OpenSlide: NDPI, SCN, Philips TIFF, BIF, CZI и т. д., а также KFB сканеров KFBio), раскладывает их по папкам и выдаёт доступ; пользователи смотрят доступные им сканы в браузере с подгрузкой только видимых фрагментов. Для обучения и разборов, не для первичной диагностики.

## Запуск на Windows

Нужен Python 3.12. Из папки проекта:

```
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
copy config.example.yaml config.yaml
```

Для запуска по http поставьте в `config.yaml` `auth.https_only: false`. Затем создайте первого администратора и запустите сервер:

```
.venv\Scripts\python.exe -m server.manage add-user ivanov --role admin --name "Иванов И. И."
.venv\Scripts\python.exe -m uvicorn server.main:app --port 8000
```

Сервис откроется по адресу http://localhost:8000. Сканы загружает администратор через веб-интерфейс: папку хранилища заполнять вручную не нужно.

В командной строке создаётся только первый администратор, дальше учётные записи заводит администратор в интерфейсе. Команды: `add-user`, `set-password`, `del-user`, `list-users`, `warm` (разовый прогрев ранее загруженных сканов). Роли: `user` (просмотр доступных сканов) и `admin` (всё). Самостоятельной регистрации нет.

Пользователи объединяются в группы: при создании базы заводятся «Патологи», «Гематологи», «Резиденты», администратор может создать свои. Доступ выдаётся пользователям и группам; действует объединение прав. «Администраторы» это не группа, а роль: у неё доступ есть всегда.

Проверка после изменений: `.venv\Scripts\python.exe -m pip install -r requirements-dev.txt`, затем

```
.venv\Scripts\python.exe -X utf8 tests\access_test.py
.venv\Scripts\python.exe -X utf8 tests\upload_test.py
.venv\Scripts\python.exe -X utf8 tests\smoke_test.py
.venv\Scripts\python.exe -X utf8 tests\cellularity_test.py
```

Тесты прав и загрузки работают на временной базе и временном хранилище и собирают тестовый SVS сами, поэтому рабочие данные и ваши сканы не затрагиваются.

## Конфигурация

Все параметры с пояснениями перечислены в [config.example.yaml](config.example.yaml). Путь к файлу можно задать переменной `VIEWER_CONFIG`. Секреты в файл не пишутся: ключ подписи сессий берётся из `VIEWER_SECRET_KEY`, а если переменной нет, создаётся в `data/secret.key`.

В папке `data/` лежат база каталога `viewer.sqlite3`, кэш тайлов и миниатюр. Кэш можно удалять в любой момент, базу нужно резервировать.

## Папки, названия и доступ

Дерево папок хранится в базе, а файлы лежат на диске под внутренними идентификаторами (`ab/ab12cd34ef56.svs`) с расширением своего формата: часть форматов OpenSlide узнаёт по расширению. Поэтому переименование и перемещение папок мгновенны и не ломают ссылки на поле зрения.

Исходное имя файла может содержать фамилию, поэтому оно не попадает ни в пути, ни в адреса страниц, ни в ответы сервера обычному пользователю, ни в журнал. В карточке скана его видит только администратор. Название в каталоге задаёт администратор; по умолчанию подставляется нейтральное («Скан 01»). Если имя файла было по шаблону `<код>_<стекло>_<окраска>.<формат>`, поля заполняются из него; окраска распознаётся только однозначная (HE, AE, GOMORI, CONGO), остальное администратор выбирает сам.

Окраска хранится кодом из списка (`server/stains.py`): H&E, АЭ, Гомори, Конго, ИГХ; у ИГХ отдельно маркер свободным текстом (колонка `ihc_marker`, схема базы версии 6). На миниатюрах и в карточках показывается сокращение, у ИГХ — только маркер; полные названия и сокращения — в словаре `i18n.js`.

Принимаемые форматы перечислены в `SLIDE_EXTENSIONS` (`server/storage.py` и `web/static/js/upload.js`, списки должны совпадать): `.svs`, `.ndpi`, `.scn`, `.tiff`, `.tif`, `.bif`, `.czi`, `.avs`, `.svslide`, `.kfb`. Многофайловые форматы (MRXS, VMS/VMU, DICOM, Trestle) не принимаются: загрузка идёт по одному файлу. Файл, который OpenSlide не открывает, отклоняется при завершении загрузки. Проверено на Aperio SVS, обычном пирамидальном TIFF и настоящем KFB; остальные форматы нужно проверить на реальных образцах.

**KFB.** OpenSlide этот формат не читает: `server/kfb.py` использует KFB-часть ASlide (GPL-3.0) с закрытой библиотекой KFBio. Работает только в Linux, то есть в образе Docker; на Windows `.kfb` отклоняется сразу. В образ её ставит `tools/install_aslide_kfb.py` — коммит ASlide и SHA-256 каждого файла закреплены в нём. Ограничения и риски (лицензия закрытого SDK, GPL, чужой машинный код) записаны в разделе 3 ТЗ.

Доступ задаётся папке или отдельному скану: «только администраторы», «все пользователи» или «выбранные». Подпапка без своего режима наследует режим папки выше, а заданный у неё режим полностью заменяет унаследованный: внутри папки «для всех» можно закрыть одну подпапку. Право проверяется на каждый запрос, включая тайлы и этикетку; чужой скан отвечает так же, как несуществующий.

Браузер обращается только к приложению, к хранилищу напрямую никогда. Поэтому перенос сканов в бакет затронет один модуль `storage.py`.

**Почему свой генератор тайлов.** У Aperio SVS шаг уровней пирамиды чуть больше целого (4,0001 вместо 4). Стандартный `DeepZoomGenerator` из-за этого читает полное разрешение и сжимает его: около 190 мс на тайл 10×. `tiles.py` выбирает уровень с допуском 2 % и читает тайл напрямую: 15–30 мс. Геометрия тайлов совпадает со стандартной.

**Продолжение загрузки после перезапуска браузера.** Сервер помнит принятые части три дня, но файл на диске открывает человек: страница сама этого сделать не может. В Chrome и Edge страница запоминает «ручку» файла (File System Access API, хранится в IndexedDB рядом с загрузкой), и после перезапуска браузера достаточно нажать «Продолжить» и разрешить чтение — окно выбора файла не открывается. В Firefox и Safari такой возможности нет: там «Продолжить» просит выбрать файл, а подсказка на кнопке называет нужный.

Файл, выбранный или перетащенный в любую папку, сам находит свою прерванную загрузку по имени и размеру и докачивается туда, где загрузка начиналась. Перед докачкой последняя принятая часть сверяется с тем же участком выбранного файла: два разных скана могут совпасть именем и размером, а дописывать чужие байты нельзя. При несовпадении страница предлагает начать этот файл заново. Пока идёт загрузка, страница просит систему не засыпать (Wake Lock); отказ браузера не мешает загрузке.

Прерванную загрузку продолжает любой администратор, а не только начавший её: в журнал пишется, кто продолжил и кто начинал.

**Почему первое открытие теперь быстрое.** Мелкие уровни пирамиды Aperio хранит невыгодно для чтения: обзорный тайл при первом обращении стоит около 350 мс, миниатюра — до полусекунды, и первое открытие скана растягивалось на 1,5–3 секунды. Поэтому сразу после приёма файла `warmup.py` в фоне готовит миниатюру и тайлы всех обзорных уровней — до уровня, на котором тайлов не больше сотни. Работает один поток, по одному скану за раз, с паузой между тайлами: просмотр других сканов при этом не замедляется. Сбой прогрева ни на что не влияет — скан уже в каталоге, тайлы просто будут готовиться по первому обращению. Сканы, загруженные до появления прогрева, готовятся разовой командой:

```
.venv\Scripts\python.exe -m server.manage warm
```

**Почему проверка прав не стоит времени.** Право проверяется на каждый тайл, и раньше это открывало пять подключений к базе — 5,8 мс, больше, чем сама отдача готового тайла. Теперь подключение к SQLite держится на поток, а учётная запись и права пользователя живут в памяти процесса (`perms.py`). Любой изменяющий запрос сбрасывает эту память, поэтому отзыв доступа, блокировка и смена роли действуют со следующего же запроса, как и раньше; правка базы со стороны (`server.manage`) подхватывается не позже трёх секунд. Сервис работает одним процессом, поэтому память общая для всех запросов.

**Увеличение.** `увеличение = объектив сканирования × (экранных пикселей на пиксель изображения)`, как в ImageScope: на 40× один пиксель скана равен одному пикселю экрана. Объектив берётся из метаданных, при его отсутствии вычисляется из размера пикселя (0,25 мкм ≈ 40×), иначе показывается процент от полного разрешения. Цифровой зум ограничен 2× от увеличения сканирования.

**Настройка изображения.** OpenSeadragon рисует тайлы на 2D-canvas; после каждого кадра он копируется в текстуру и перерисовывается фрагментным шейдером на WebGL-canvas поверх. Тайлы повторно не загружаются, мини-карта и миниатюры остаются без коррекций. Порядок применения и формулы:

1. Баланс каналов: `c × 2^(b/100)`, усиление от 0,5 до 2.
2. Яркость и контраст: `(c − 0,5) × 3^(контраст/100) + 0,5 + яркость/200`.
3. Гамма: `c^(1/гамма)`, значения больше 1 осветляют средние тона.
4. Насыщенность: смешение с яркостью (Rec. 709) с коэффициентом `1 + s/100`; затем оттенок: поворот вокруг серой оси.

Настройки хранятся в браузере отдельно для пользователя и слайда. Значения пресетов в `adjust.js` предварительные, их нужно согласовать на тестовых сканах.

**Горячие клавиши.** `0` весь скан, `1`–`4` 4×/10×/20×/40×, `+`/`−` зум, стрелки панорамирование, `Page Down`/`Page Up` следующий и предыдущий скан папки, `F` полный экран, `R` сброс вида, `L` этикетка, `I` настройка изображения, `C` сравнение, `Q` другая половина при сравнении, `S` сведения о скане, `M` рулетка, `?` список клавиш. Работают в любой раскладке; `Tab` принадлежит браузеру и ходит по кнопкам.

**Панель увеличений.** Ползунка плавного зума нет: он дублировал колесо мыши. Кнопки увеличений начинаются с 4×, как на микроскопе. Ниже жёлтого поля с текущим увеличением стоят кнопки инструментов — «Рулетка», «Привязка по ориентирам» (только при сравнении) и «Поворот». Панель сворачивается кнопкой до одного значка, как мини-карта, и при каждом открытии страницы снова развёрнута.

**Поворот и отражение.** Окошко поворота даёт угол от −180° до 180° ползунком и числом, кнопки −90°, +90°, 0° и отметку «Отразить». Поворот действует на обе половины сразу (сравнивать имеет смысл в одинаковой ориентации), отражение — только на выбранную: срез иногда приклеен к стеклу другой стороной, и тогда правильный и перевёрнутый срезы не сопоставить. Отражённый скан помечен словом «отражено» в заголовке половины и в строке состояния — на снимке экрана его иначе не отличить от настоящего. Угол и отражение попадают в ссылку на поле зрения.

Библиотека просмотра зеркалит только рисование, но не пересчёт координат, поэтому точки скана переводятся в точки экрана через `SlideView.pixelFromImage` и обратно через `imageFromPixel`: ими пользуются аннотации, рулетка, ориентиры и общий курсор. Положение щелчка библиотека возвращает уже в незеркальных координатах — там пересчёт прямой.

**Рулетка.** Расстояние между двумя точками: включается кнопкой, клавишей `M` или из меню по правой кнопке, точки ставятся обычными щелчками (двойной щелчок по-прежнему приближает). Длина считается по размеру пикселя из файла, поэтому не зависит от увеличения, поворота и отражения; от 1000 мкм показывается в миллиметрах. Законченное измерение остаётся на препарате и после выхода из режима рулетки: стирают его `Esc` или новое измерение. В базу оно не пишется и доступно всем пользователям. Если размера пикселя в файле нет, кнопка неактивна и объясняет почему.

**Меню по правой кнопке на препарате.** «Рулетка» — всем, «Указатель» и «Контур» — тем, у кого есть инструменты аннотаций. Стрелка ставится сразу в точку, где открыли меню; контур и рулетка начинаются с неё. Меню браузера подавляется только над самим препаратом: на мини-карте, этикетке и панелях правая кнопка работает как обычно. На сенсорном экране меню нет, поэтому у каждого пункта остаётся обычный путь — кнопка и клавиша.

**Связь половин.** Взаимное положение записывается одним преобразованием микрометров первой половины в микрометры второй: `b = R(угол) · F · a + сдвиг`, где `F` зеркалит x, если срезы отражены друг к другу. Масштаб в преобразование не входит: микрометры у обеих половин общие, размер пикселя берётся из файлов. Вся математика в `link.js`, она же считает поворот второй половины, привязку по ориентирам и общий курсор.

Связать половины можно тремя способами. Кнопка «Связать» запоминает то, как они стоят сейчас. Кнопка «Привязка по ориентирам» (видна только при сравнении) просит отметить одну и ту же структуру в обеих половинах: двух пар хватает для неотражённых срезов, третья определяет отражение сама и показывает расхождение ориентиров в микрометрах — по нему видно, насколько срезы растянуты. При трёх и более парах поворот считается наименьшими квадратами. Третий способ — поправка на ходу: при зажатом `Shift` двигается и поворачивается только активная половина, при отпускании связь запоминает новое взаимное положение; разрывать и связывать заново не нужно.

При связанных половинах место, на которое указывает мышь в одной, отмечается тонким перекрестием в другой. Оно считается тем же преобразованием, что и связь, поэтому точно настолько, насколько точна привязка: у места привязки — до клетки, вдали от него — до участка. Без связи и на сенсорном экране перекрестия нет.

**Аннотации.** Патологи (участники группы «Патологи») и администраторы ставят на скан две пометки: указатель-стрелку на клетку (её вершина стоит на отмеченной точке, древко уходит вверх-влево и клетку не закрывает) и контур-полигон, к каждой пишется комментарий. Вокруг выбранной пометки белое свечение — так видно, с какой сейчас работают; щелчок по препарату мимо пометок его снимает. Пометки неоново-зелёные, без обводки (этот цвет почти не встречается в препаратах), в окне «Изменить» можно выбрать ярко-красный; у каждой рядом стоит номер — её место в списке скана, тот же номер в списке сбоку и в подсказке. После удаления аннотации следующие номера сдвигаются. Геометрия хранится в координатах скана, поэтому пометка держится за ту же клетку при любом увеличении и повороте; размер маркера и толщина линии на экране не меняются. Остальные пользователи с доступом к скану аннотации видят, но инструментов у них нет; автор правит и удаляет свои, администратор — любые. Комментарий не написан на препарате постоянно: он виден при наведении, по щелчку и в списке сбоку. Показ всех аннотаций выключается клавишей A, выбор запоминается в браузере. Ссылка вида `/viewer?slide=…&annotation=…` открывает нужное место и выделяет пометку. Контуры рисуются одной группой SVG с матрицей преобразования — на кадр пересчитываются три точки, а не все вершины.

**Телефон.** Та же страница в браузере телефона, устанавливать ничего не нужно. На узком экране кнопки фиксированных увеличений идут рядом внизу вместе с «Рулеткой» и «Поворотом» (окошко поворота открывается вверх), в строке состояния остаётся только увеличение, список сканов случая открывается поверх препарата и закрывается после выбора. Препарату остаётся не меньше 80 % высоты экрана. Разделённый экран на телефоне не делается: две половины по 180 точек бесполезны. Ряд увеличений включается и на лежащем телефоне — по высоте экрана, а не только по ширине.

**Верхняя панель вьювера.** Кнопки — значки (`icons.js`), полное название остаётся в подсказке и в `aria-label`. Кнопки, которым не хватило ширины, уезжают в меню «ещё»: раскладка пересчитывается при каждом изменении размера окна. Путь до папки скана виден под названием и открывает эту папку в каталоге.

**Оценка клеточности (этап 11, раздел 13.8 ТЗ).** Перенос MarrowQuant 2.0 (Sarkis и др., Modern Pathology, 2023) с QuPath и ImageJ на Python. `server/cellularity.py` повторяет шаги оригинала вместе с неочевидными правилами ImageJ (они описаны в начале файла), `server/ij_watershed.py` — построчный перенос разделения слипшихся частиц и карты расстояний ImageJ на Numba: результат этого шага зависит от порядка заливки, и без точного переноса число жировых клеток расходилось с оригиналом в два с лишним раза. `server/cellularity_slide.py` — то, что в оригинале делает QuPath: контуры, чтение области, площади и формулы. Совпадение с ImageJ проверено по точкам эталоном `tools/mq_reference` (README там же).

Во вьювере (кнопка со знаком процента в столбце увеличений, только у сканов H&E): контуры «Ткань» и «Артефакт» рисуются как аннотации своих видов или предлагаются по миниатюре; расчёт запускают участники группы «Патологи» и администратор, ход виден по стадиям, результат и маски видят все, у кого есть доступ к скану. Маски приходят тайлами той же сетки, что скан (`/api/slides/{id}/cellularity/runs/{run}/masks/…`), и лежат вторым слоем OpenSeadragon; карты классов хранятся в `data/cellularity/`, записи расчётов — в таблице `cellularity_runs` (схема 7). Если контуры меняли после расчёта, результат помечается как устаревший. Администратор выгружает все расчёты в CSV (`/api/cellularity/export.csv`). Панель — `web/static/js/cellularity.js`, сервис — `server/cellularity_runs.py`.

Та же оценка командой на сервере (для сверки без интерфейса):

```
docker compose exec -T viewer python -X utf8 -m server.manage cellularity <ID скана> [--resolution original|1|2] [--contours контуры.geojson] [--json итог.json] [--memory-limit 500] [--time-limit 1800]
```

`original` — как MarrowQuant: полное разрешение, уменьшенное в 4 раза (скан 20× считается при 2 мкм на точку, 40× — при 1 мкм); `1` и `2` — мкм на точку для любого сканера. Контуры — GeoJSON из QuPath (классы «Tissue Boundaries» и «Artifact»); без них фрагменты ищутся по миниатюре. Итог по стеклу считается по сумме площадей фрагментов, а не как среднее процентов. Скомпилированный код Numba хранится в `data/cache/numba`: первый расчёт после пересборки образа на ~15 с дольше.

Расчёт идёт в отдельном процессе с пониженным приоритетом (`server/cellularity_job.py`): по одному за раз, с пределами памяти и времени, ход по стадиям, отмена. Память оценивается до запуска — 150 МБ библиотек плюс 12 байт на точку крупнейшего фрагмента в разрешении расчёта; если оценка выше предела, расчёт не запускается и предлагается более грубое разрешение. Область фрагмента целиком в память не читается: строки идут со скана по требованию, всё с плавающей точкой и морфология считаются полосами с полем, связные части выделяются без карты меток. `--in-process` считает в текущем процессе без приоритета и пределов — для отладки.

**Интерфейс на других языках.** Все строки лежат в словаре `static/js/i18n.js`; для казахского или английского добавляется словарь с теми же ключами.

## Развёртывание на VPS

Нужен VPS казахстанского провайдера с Docker. Доменное имя необязательно: сервис работает и по IP-адресу.

1. Скопировать проект на сервер. С рабочего сервера `github.com` не открывается (работает только `api.github.com`), поэтому `git clone` не проходит: код переносится архивом.

   ```
   cd /opt/viewer-svs
   curl -L https://api.github.com/repos/sajberex-eng/Viewer-SVS/tarball/main | tar xz --strip-components=1
   ```

   `config.yaml` и `.env` в архиве нет, распаковка их не затрагивает. Папки `.venv` и `data` не переносятся.
2. Создать рядом с `docker-compose.yml` файл `config.yaml` (за образец взять `config.example.yaml`). На сервере: `storage.root: /app/data/slides`, `auth.https_only: true`, `cache.max_gb: 2`, `open_slides: 4`.
3. Создать рядом файл `.env`:

   ```
   VIEWER_HOST=<IP-адрес или домен, без https://>
   VIEWER_TLS=internal
   VIEWER_SECRET_KEY=<случайная строка, например из openssl rand -base64 48>
   ```

   `VIEWER_TLS=internal` даёт самоподписанный сертификат: трафик шифруется, но браузер один раз предупредит, и каждый пользователь подтвердит исключение. Для домена ставится `VIEWER_TLS=acme`, и Caddy получает сертификат сам.
4. `docker compose up -d --build`, затем создать первого администратора:

   ```
   docker compose exec viewer python -m server.manage add-user admin --role admin --generate
   ```

Сканы загружает администратор через веб-интерфейс, папка на хосте для них не нужна: хранилище лежит в томе `viewer-data`. Перезапуск сервиса обеспечивает `restart: unless-stopped`.

Резервное копирование: копировать `/var/lib/docker/volumes/<проект>_viewer-data/_data/viewer.sqlite3`. В базе нет изображений, только папки, права, учётные записи и журнал; сканы восстанавливаются повторной загрузкой из архива Центра.
