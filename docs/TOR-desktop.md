# ТЗ: настольная программа HemCenterHistoDigital (Windows, затем macOS)

Редакция 3, 2026-09-26. Дочерний документ к [PRD.md](../PRD.md) веб-сервиса
HemCenterHistoDigital (репозиторий `sajberex-eng/Viewer-SVS`). Переносит на
один компьютер тот же тайл-сервер и тот же клиент — без VPS, без сети и без
многопользовательского доступа.

## 0. Решения заказчика

2026-09-26, по вопросам редакции 2:

1. **Название — HemCenterHistoDigital**, как у веб-сервиса. Папка установки
   `%LOCALAPPDATA%\Programs\HemCenterHistoDigital`. Имя `KFSlideOS` не
   используется: это установленная на том же компьютере программа KFBIO
   (`KFSlideOS.exe` 1.1.2.0, «Copyright © 2026 KFBIO»), её папку наш
   установщик не трогает.
2. **Сканы открываются из папок на компьютере**, которые выбирает
   пользователь, — на месте, без копирования в папку программы (раздел 6).
3. **KFB в Windows — пробуем обёртку** над библиотекой KFBio из KFSlideOS
   (раздел 7, этап 4). Перевод KFB в SVS остаётся запасным путём.
4. **macOS:** библиотека KFB для macOS у заказчика есть, но распаковать её
   без Mac он не может. Версия для macOS откладывается (этап 5).
5. **Подпись кода не покупается.** При первом запуске Windows покажет
   предупреждение SmartScreen; инструкция объясняет, как его пройти.
6. **Программа ставится на компьютер, где установлена KFSlideOS.** Поэтому
   KFB читается библиотекой из KFSlideOS, в нашу сборку она не входит.

Что изменилось против редакции 1: название; вход одноразовым ключом при
запуске вместо `?session=` в адресе (раздел 5); сканы на месте вместо
копирования; упаковка папкой с установщиком вместо одного `.exe` (раздел 9);
требования пронумерованы (НП-…) и получили критерии приёмки. Исправлена
ошибка редакции 1 («сессия работает в Linux-контейнере»): разработка идёт на
Windows 11 заказчика, Windows-сборка собирается и проверяется здесь же; для
macOS нужен Mac.

## 1. Назначение

Программа для просмотра сканов гистопрепаратов (Aperio SVS и другие
форматы, которые читает OpenSlide; KFB — через библиотеку KFSlideOS) на
одном компьютере под Windows 10/11, позже под macOS. Работает без интернета,
без сервера и без входа по паролю: один врач, свои сканы, свой диск.

Не замена веб-сервису, а второй способ запуска того же кода — на случай,
когда сети нет или сканы не должны покидать компьютер.

## 2. Отношение к веб-сервису

- **Код общий.** `server/` и `web/` — те же, что у веб-сервиса. Исправление
  во вьювере делается один раз и попадает в обе сборки. Различия включаются
  настройкой `desktop: true` в `config.yaml` (НП-1), а не копией кода.
- **Один репозиторий**, без форка. Новая папка `desktop/` — только то, что
  нужно настольной сборке: запуск с окном, описание сборки, установщик,
  инструкция.
- **Данные не связаны.** Своя база на компьютере; обмена с сервером нет
  (раздел 12).
- **Правила репозитория действуют как прежде**: сканы заказчика, их имена,
  адрес сервера и ключи в репозиторий не попадают. Не действуют только
  правила размещения данных веб-сервиса (сервер в Казахстане): за данные на
  компьютере отвечает его владелец. Рекомендация в инструкции — шифрование
  диска (BitLocker).

| НП-2 | **Экрана входа нет.** При первом запуске создаётся одна учётная запись с ролью `admin` и случайным паролем, который нигде не показывается и не сохраняется. Вход — по одноразовому ключу запуска (раздел 5) |
| НП-3 | **Прячется то, что не имеет смысла для одного человека:** кнопка «Выход» и кружок пользователя с профилем и сменой пароля, вкладки «Пользователи» и «Группы» в администрировании, окно «Доступ» у папок и сканов, строка «Эти сканы видят только администраторы». | НП-5 | **Загрузки нет.** Вместо кнопки «Загрузить» и перетаскивания файлов — «Добавить папку» (раздел 6). Приём файлов частями, докачка и проверка свободного места под сканы в настольной версии не используются |
| НП-6 | **Исходные имена файлов** видны: пользователь сам выбрал папку и администратор. Название скана по умолчанию — имя файла без расширения; своё название, окраска и маркер задаются как сейчас и хранятся в базе программы, файл не переименовывается |
| НП-7 | **Выгрузка файлов** (CSV клеточности, журнала) сохраняется через системное окно «Сохранить как»: встроенное окно браузера без этого файлы молча не скачивает |
| НП-8 | Всё остальное — без изменений: поиск, вьювер, сравнение двух сканов, аннотации, рулетка, поворот, этикетка, клеточность (алгоритм и ИИ), форматы `SLIDE_EXTENSIONS` |

## 4. Устройство

```
desktop/
  launcher.py        # окно, сервер в потоке, ключ запуска, одна копия программы
  app.spec           # PyInstaller: состав, OpenSlide, исходники для Numba
  installer.iss      # Inno Setup: установка без прав администратора
  README.md          # сборка и запуск готовыми командами
server/, web/        # общие с веб-сервисом
```

`launcher.py` при запуске:

1. Проверяет, что программа не запущена второй раз (файл-замок в служебной
   папке). Если запущена — выводит её окно вперёд и завершается: два
   сервера на одной базе SQLite недопустимы.
2. Создаёт при первом запуске служебную папку и `config.yaml` в ней
   (раздел 6); переменная `VIEWER_CONFIG` указывает на этот файл.
3. Запускает `uvicorn` на `127.0.0.1` и свободном порту в фоновом потоке.
4. Создаёт одноразовый ключ запуска и открывает окно `pywebview` (WebView2
   в Windows, WKWebView в macOS) на адресе входа (раздел 5).
5. Даёт странице системное окно выбора папки (`pywebview` → `FOLDER_DIALOG`)
   и «Сохранить как» (НП-7).
6. При закрытии окна останавливает сервер, отменяет идущий расчёт
   клеточности и завершает его дочерний процесс, освобождает замок.

Важная деталь для упаковки: `server/config.py` отсчитывает относительные
пути от `BASE_DIR` — папки с кодом. В собранной программе это папка
установки, поэтому пути в настольной версии всегда абсолютные и задаются
`launcher.py`.

Журнал сервера пишется в файл `logs/app.log` служебной папки с ротацией:
консоли у программы нет.

## 5. Вход без пароля

| № | Требование |
| --- | --- |
| НП-9 | При каждом запуске `launcher.py` создаёт случайный ключ (32 байта) и передаёт его серверу в памяти процесса. Окно открывается на `/desktop/enter?key=…`; сервер сверяет ключ (`secrets.compare_digest`), **сразу его гасит**, ставит обычную cookie сессии `viewer_session` и перенаправляет на `/`. Повторный заход по тому же адресу получает отказ |
| НП-10 | Сервер слушает только `127.0.0.1` и принимает запросы только с заголовком `Host: 127.0.0.1:<порт>` (защита от подмены DNS из браузера). Страница, открытая в обычном браузере пользователя, cookie окна не получает: у окна свой профиль WebView2 в служебной папке |
| НП-11 | Ключ подписи сессий (`secret.key`) хранится в служебной папке, как сейчас в `data/`. Срок сессии — до закрытия программы |

Почему не `?session=…` в адресе: такой ключ остаётся в истории окна и в
журнале сервера и действует, пока действует сессия; одноразовый ключ после
первого использования ничего не открывает.

## 6. Папки со сканами и служебная папка

Сканы остаются там, где их положил пользователь (решение заказчика
2026-09-26). Программа хранит только свою базу, кэш и настройки.

| № | Требование |
| --- | --- |
| НП-12 | **«Добавить папку»** в каталоге открывает системное окно выбора папки. Папок можно добавить несколько (например, на разных дисках, в том числе на сетевом и съёмном). В дереве каталога каждая подключённая папка — корневой узел с её именем; внутри — подпапки и сканы так, как они лежат на диске. Файлы с расширениями `SLIDE_EXTENSIONS` видны, остальные — нет |
| НП-13 | **Файлы на диске программа не меняет:** не переименовывает, не перемещает, не удаляет и ничего не пишет рядом с ними. «Удалить» у скана и папки в настольной версии — «Убрать из каталога» (снимает с учёта, аннотации и расчёты остаются в базе до повторного появления файла или до явной очистки). Создание, переименование и перемещение папок в дереве недоступны: дерево повторяет диск |
| НП-14 | **Каталог обновляется** при запуске, при открытии папки в дереве и по кнопке «Обновить» у подключённой папки: новые файлы появляются, пропавшие помечаются «файл не найден» (сведения о скане сохраняются). Следить за папкой непрерывно не требуется |
| НП-15 | **Скан узнаётся после переименования и переноса** внутри подключённых папок — по отпечатку: размер файла и контрольная сумма первого и последнего мегабайта. Аннотации, окраска, название и расчёты клеточности не теряются. Одинаковые копии одного файла в двух местах — один скан с пометкой о втором расположении |
| НП-16 | **Миниатюры строятся в фоне** после добавления папки, по одному файлу, с пониженным приоритетом — как прогрев после загрузки сейчас (`server/warmup.py`), но только миниатюра: обзорные тайлы готовятся при первом открытии скана. Папка с сотней сканов не должна тормозить работу |
| НП-17 | **Файл, который не открылся** (повреждён, KFB без библиотеки, неподдерживаемый вариант формата), виден в каталоге с пометкой и причиной, а не пропадает молча |
| НП-18 | **Служебная папка** — `%LOCALAPPDATA%\HemCenterHistoDigital` (Windows), `~/Library/Application Support/HemCenterHistoDigital` (macOS). Внутри: `config.yaml`, `secret.key`, `viewer.sqlite3`, `cache/tiles`, `cache/thumbs`, `cache/numba`, `logs/`, профиль окна `webview/`. Сканов в ней нет, поэтому она небольшая; кэш тайлов ограничен 2 ГБ, как на сервере. Переустановка и обновление её не трогают, схема базы переносится сама |
| НП-19 | **Подключённая папка в OneDrive или другом облачном хранилище** работает, но при добавлении программа предупреждает: у файлов «только в облаке» первое открытие скачивает скан целиком |

Что меняется в коде: сейчас скан — это файл под внутренним ID в
`storage.root`, путь строит адаптер хранилища (`server/storage.py`). Для
настольной версии нужен второй адаптер: скан хранит подключённую папку и
относительный путь, папки каталога строятся по диску. Внутренний ID скана
остаётся, в API по-прежнему уходят `id` и `title`, а не путь. Пространство
имён кэша тайлов уже включает размер и дату файла, поэтому изменённый файл
не покажет старые тайлы.

## 7. Формат KFB

Что есть:

- **Linux (веб-сервис):** KFB читается через ASlide: `libkfbslide.so` — слой с
  интерфейсом наподобие OpenSlide поверх закрытой `libImageOperationLib.so`.
- **Windows, KFSlideOS:** `resources\server\backend\ImageOperationLib.dll`
  (64 бит, 14,9 МБ), 35 функций — те же, что у Linux-библиотеки:
  `InitImageFileFunc`, `GetHeaderInfoFunc`, `GetImageStreamFunc`,
  `GetImageDataRoiFunc`, `GetLableInfoFunc`, `GetThumnailImageFunc`,
  `DeleteImageDataFunc` и другие. Слоя `kfbslide` для Windows нет — обёртку
  поверх этих функций пишем сами. Описаний функций (заголовочного файла)
  нет: порядок и типы аргументов восстанавливаются по тому, как их вызывает
  ASlide в Linux, и проверяются на настоящем скане. Главный риск этапа 4.
- **Windows, K-Viewer** (`C:\Program Files (x86)\kfbio\K-Viewer`): библиотека
  2016 года, **32-битная**, 17 функций. 32-битную библиотеку нельзя
  загрузить в 64-битный Python, на котором работают NumPy, OpenCV и Numba,
  и она может не читать сканы новых сканеров. Не используется.
- **macOS:** библиотека есть у заказчика в запакованном виде (этап 5).

| № | Требование |
| --- | --- |
| НП-20 | Библиотека KFBio **не входит в нашу сборку и не копируется**. Программа ищет `ImageOperationLib.dll` в папке установки KFSlideOS (`%LOCALAPPDATA%\Programs\KFSlideOS\resources\server\backend`) или в папке, указанной в `config.yaml` (`kfb.library_dir`). Нет библиотеки — сканы KFB видны в каталоге с пометкой «нужна KFSlideOS» (НП-17), остальные форматы работают |
| НП-21 | Библиотека загружается из своей папки, не подменяя наши: у KFSlideOS рядом лежат свои `opencv_world330.dll`, `libcurl.dll`, `libssl` и другие. Загрузка через `os.add_dll_directory` с проверкой, что наш OpenCV и OpenSlide не перехвачены. Если конфликт не обойти — чтение KFB идёт в отдельном процессе |
| НП-22 | `server/kfb_win.py` — обёртка под интерфейс OpenSlide поверх функций `ImageOperationLib.dll`, по образцу `server/kfb.py`: чтение под замком, этикетка своим кодом. Выбор между `kfb.py` и `kfb_win.py` — по системе, снаружи интерфейс один |
| НП-23 | Запасной путь, если обёртка не заработает: скан KFB переводится в SVS/TIFF конвертером KFBio и открывается как обычный файл. Кода не требует |

Юридическая сторона: библиотека — собственность KFBIO. Программа только
пользуется библиотекой, установленной вместе с KFSlideOS на том же
компьютере (решение заказчика 2026-09-26, пункт 6), и не распространяет её.

## 8. Оценка клеточности

- Алгоритм (`server/cellularity.py`, `cellularity_job.py`) уже переносим:
  приоритет процесса и замер памяти в Windows сделаны, настройка памяти glibc
  и `RLIMIT_DATA` включаются только в Linux. В Windows ограничение памяти
  расчёта держит наблюдатель за рабочим набором — этого достаточно.
- **Numba в собранной программе.** Кэш скомпилированных функций пишется в
  `cache/numba` служебной папки. Numba кэширует только функции, у которых
  есть исходный `.py` файл, а PyInstaller по умолчанию кладёт модули в архив
  без исходников. Поэтому `server/` упаковывается исходниками
  (`module_collection_mode`). Без этого каждый расчёт заново компилирует
  функции (десятки секунд). Проверяется на этапе 3.
- Дочерний процесс расчёта запускается через `spawn`; в собранной программе
  нужен `multiprocessing.freeze_support()` в точке входа, иначе дочерний
  процесс запускает вторую копию программы.
- **ИИ-оценка** (Anthropic, Gemini) выключена, пока пользователь не введёт
  ключ во вкладке «Настройки». Рядом с полем ключа — предупреждение: при
  оценке ИИ фрагменты изображения ткани отправляются поставщику ИИ за
  пределы страны. Без интернета кнопка ИИ неактивна с подсказкой.

## 10. Нефункциональные требования

- Запуск до появления каталога — не дольше 10 секунд на обычном ноутбуке,
  в том числе первый.
- Добавление папки со 100 сканами: дерево появляется сразу, миниатюры
  догружаются в фоне, окно при этом не подвисает.
- Сеть наружу не открывается: только `127.0.0.1`. Исходящие запросы — только
  к ИИ и только после ввода ключа.
- После закрытия окна в диспетчере задач не остаётся процессов программы, в
  том числе дочернего процесса расчёта.
- Скорость показа тайлов — не хуже веб-сервиса на том же скане.

## 11. Этапы и приёмка

**Этап 1 — настольный режим сервера** (НП-1…НП-4, НП-9…НП-11).
- [ ] При `desktop: false` четыре набора тестов проходят без изменений
- [ ] При `desktop: true`: вход по ключу работает один раз, повторный заход
      по тому же адресу отклонён; запрос с чужим `Host` отклонён
- [ ] Нет кнопки «Выход», профиля, вкладок «Пользователи» и «Группы», окна
      «Доступ», ссылок на поле зрения; «Журнал» и «Настройки» есть
- [ ] Новые проверки на ключ запуска и `Host`

**Этап 2 — папки со сканами** (НП-5, НП-6, НП-12…НП-19). Проверяется ещё
в браузере на стенде, без окна.
- [ ] Две подключённые папки на разных дисках видны в дереве с
      подпапками как на диске
- [ ] Новый файл появляется после «Обновить»; удалённый помечен «файл не
      найден», его аннотации на месте
- [ ] Переименованный и перенесённый в другую подпапку скан сохраняет
      аннотации, окраску и расчёт клеточности
- [ ] «Убрать из каталога» не трогает файл на диске (проверка: размер и
      дата файла до и после)
- [ ] Повреждённый файл виден с пометкой и причиной
- [ ] Имя файла не уходит в адреса тайлов и миниатюр
- [ ] Тесты адаптера на временных папках (синтетические SVS из
      `tests/synthetic_svs.py`)

**Этап 3 — окно, сборка и установщик** (НП-7, раздел 4, НП-24…НП-28,
раздел 8).
- [ ] `python -m desktop.launcher` открывает окно; «Добавить папку»
      открывает системное окно выбора
- [ ] CSV сохраняется через «Сохранить как»
- [ ] Второй запуск выводит вперёд первое окно
- [ ] После закрытия окна процессов не остаётся, в том числе во время расчёта
- [ ] Установка без прав администратора, запуск с ярлыка на чистой учётной
      записи Windows
- [ ] Повторный расчёт клеточности не компилирует функции заново
- [ ] Удаление и повторная установка программы сохраняют подключённые
      папки и аннотации
- [ ] Время запуска и размер установщика записаны в этот раздел

**Этап 4 — KFB в Windows** (НП-20…НП-23).
- [ ] Скан KFB заказчика открывается, тайлы, миниатюра, этикетка и размер
      пикселя совпадают с тем, что показывает KFSlideOS
- [ ] Другие форматы при загруженной библиотеке KFBio открываются как
      прежде (нет конфликта DLL)
- [ ] Без KFSlideOS сканы KFB помечены «нужна KFSlideOS», остальное работает
- [ ] Расчёт клеточности на скане KFB

**Этап 5 — macOS.** Откладывается до появления Mac: на нём собирается
`.app` и распаковывается библиотека KFB. Возможно, её удастся распаковать
и в Windows (7-Zip открывает `.dmg` и `.pkg`) — для этого нужен файл от
заказчика. Без учётной записи Apple Developer программу придётся разрешать
вручную в «Системных настройках → Конфиденциальность и безопасность».

Порядок работы как в веб-проекте: проверка на стенде, затем на компьютере
заказчика; коммит и пуш — после подтверждения заказчика.

## 12. Вне рамок

- Автообновление программы.
- Несколько пользователей на одном компьютере (код прав остаётся, но не
  включается).
- Перенос аннотаций и расчётов между веб-сервисом и программой.
- Непрерывное слежение за папками (обновление — по кнопке и при открытии).
- Резервное копирование базы: пользователь копирует служебную папку сам.
- Печать, экспорт в PDF, форматы вне `SLIDE_EXTENSIONS`.

   Windows и посмотреть состав — до этапа 5 это ни на что не влияет.
