## 2. Скорость загрузки и отображения сканов

### Что измерено

Сервер: 2 ядра, 1,9 ГБ памяти, простаивает (загрузка процессора 0,2 %, занято
250 МБ). Диск 30 ГБ, занято 11. До сервера от рабочего места 30–70 мс.

| Операция | Время |
| --- | --- |
| Открытие файла скана 1 ГБ | 43–62 мс |
| Проверка прав на каждый запрос тайла | 5,8 мс (пять подключений к базе) |
| Тайл на родном уровне файла (40×, 10×) | 17–27 мс |
| Тайл на промежуточном уровне (20×, 2,5×) | 80–100 мс |
| Тайл обзорного уровня (первое открытие скана) | **350 мс** |
| Миниатюра для каталога | 400–500 мс |
| Сжатие тайла в JPEG | 2 мс |
| Тайл из дискового кэша | проверка прав 5,8 мс + отдача файла (не измерялась, по оценке около 1 мс) |

Главное наблюдение: **медленно только первое обращение.** Готовый тайл ложится
в дисковый кэш (лимит 2 ГБ) и дальше отдаётся мгновенно — всем пользователям.
Самое медленное место — как раз то, что человек видит первым: обзорные уровни
(350 мс на тайл) и миниатюра (до 0,5 с). Файл Aperio хранит мелкие уровни
невыгодно для чтения, и первое открытие скана стоит 1,5–3 секунды.

### Рекомендации

| № | Выигрыш | Что сделать |
| --- | --- | --- |
| СК-1 | Большой | **Прогрев после загрузки.** Когда скан принят, сервер в фоне сразу готовит миниатюру и все обзорные уровни (до уровня, где тайлов не больше сотни). Это 5–15 секунд процессора на скан, один раз. Первое открытие становится мгновенным для всех |
| СК-2 | Средний | Промежуточные уровни (20×, 5×, 2,5×) собираются из вчетверо большего куска файла: 80–100 мс против 20. При двух ядрах свежий экран на 20× — это 1–1,5 с. Можно прогревать и их, но только для области с тканью; разумнее сделать после СК-1 и посмотреть, останется ли жалоба |
| СК-3 | Средний | Проверка прав на каждый тайл открывает пять подключений к базе (5,8 мс). На кэшированном тайле это основная часть времени ответа (сама отдача файла — по оценке около 1 мс). Решение: держать подключение к базе на поток и помнить права пользователя 2–3 секунды. По оценке, экран из 30 готовых тайлов будет стоить серверу около 30 мс вместо 170 |
| СК-4 | Малый | Заголовок кэша тайлов дополнить словом `immutable`: при обновлении страницы браузер не будет перепроверять сотни тайлов |
| СК-5 | Малый | Каждое попадание в кэш обновляет время файла (`os.utime`) — это запись на диск на каждый тайл. Достаточно обновлять, если отметке больше часа |
| СК-6 | Малый | Ограничить число одновременных запросов тайлов у клиента (`imageLoaderLimit: 8`): при быстром перемещении сервер с двумя ядрами не будет дорабатывать тайлы, которые уже ушли с экрана |

Что **не** узкое место: сжатие JPEG (2 мс), открытие файла (50 мс), сеть
(HTTP/2 и HTTP/3 в Caddy включены по умолчанию, порт 443/udp открыт; тайл весит 5–60 КБ), память и процессор сервера.
Размер части при загрузке (8 МБ) проверялся раньше и оставлен.

## 3. Продолжение прерванной загрузки

### Как сейчас

Сервер помнит принятые части три дня, докачка идёт с последнего принятого
байта. Но в самом браузере есть три слабых места.

| № | Важность | Что не так |
| --- | --- | --- |
| ЗГ-1 | **В** | **Загрузка сдаётся через 15 секунд.** Пять попыток с паузой 3 с — и задача переходит в «ошибку». Любой обрыв связи дольше 15 секунд (перезагрузка роутера, сон ноутбука) убивает загрузку, хотя файл всё ещё открыт в браузере и его можно было просто дослать. |
| ЗГ-2 | **В** | **У задачи с ошибкой нет кнопки «Повторить».** Файл ещё в памяти страницы, выбирать его заново не нужно — но интерфейс этого не предлагает. Строка «Продолжить» появляется только после перезагрузки страницы и требует выбрать файл |
| ЗГ-3 | С | Закрытие вкладки или переход на другую страницу во время загрузки ничем не предупреждается: загрузка молча обрывается |
| ЗГ-4 | Н | Продолжить загрузку может только тот администратор, который её начал. Второму администратору сервер отвечает отказом |
| ЗГ-5 | Н | При докачке файл опознаётся только по имени и размеру. Другой файл с тем же именем и размером (исправленная копия) будет приклеен к началу старого. Проверка: сравнить контрольную сумму последней принятой части |

### Можно ли не выбирать файл заново

**В пределах одного сеанса — да, полностью** (ЗГ-1 и ЗГ-2). Это закрывает
большинство случаев: страница открыта, связь пропала и вернулась.

| Вариант | Что даёт | Ограничения |
| --- | --- | --- |
| А. Ждать связь, а не сдаваться | Повторы без ограничения числа, с растущей паузой (3 с → 1 мин); по событию браузера «связь появилась» — сразу. Сдаваться только на ответах сервера, которые повтором не лечатся (нет места, загрузка удалена) | Нет. Работает во всех браузерах |
| Б. Кнопка «Повторить» у задачи с ошибкой | Одно нажатие, файл не выбирается | Нет |
| В. Запомнить сам файл между сеансами | Chrome и Edge умеют хранить «ручку» файла (File System Access API) в базе браузера. После перезагрузки страницы или компьютера строка «Продолжить» продолжает загрузку **одним нажатием**: браузер спрашивает «разрешить сайту читать файл?» — и всё. Работает и для файлов, перетащенных мышью | Только Chrome и Edge на компьютере, только по HTTPS (на рабочем сервере он есть). В Firefox и Safari остаётся выбор файла, как сейчас |
| Г. Не давать ноутбуку заснуть | Пока идёт загрузка, страница просит систему не гасить экран (Wake Lock). Сон ноутбука — частая причина обрыва длинной загрузки | Chrome, Edge, Safari. Вкладка должна быть видимой |
| Д. Предупреждение при закрытии вкладки | «Идёт загрузка, уйти со страницы?» | Нет |
| Е. Умное опознание при повторном выборе | Если администратор всё же выбирает или перетаскивает файл, имя и размер которого совпадают с прерванной загрузкой, — докачка идёт в ту папку, где она начиналась, а не в открытую сейчас. Можно бросить сразу пачку файлов: каждый найдёт свою загрузку | Нет |

Рассмотрено и отклонено: фоновая загрузка средствами браузера (Background
Fetch) — только Chrome, не умеет докачку частями; хранить копию файла в
браузере — скан 1–3 ГБ не помещается в квоту и удвоил бы место на диске.

Рекомендуемый порядок: А + Б + Д (полдня работы, закрывают основную боль),
затем В + Е, затем Г.
