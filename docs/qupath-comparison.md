# Сверка расчёта клеточности с оригинальным MarrowQuant 2.0 в QuPath

Этап 11, требование КЛ-11 (раздел 13.8 ТЗ). Цель — убедиться, что наш расчёт на сервере даёт
те же цифры, что оригинальная программа авторов статьи, **по одним и тем же контурам**.

Что уже проверено без QuPath: сам алгоритм совпал с ImageJ до точки (эталон
`tools/mq_reference`). Эта сверка проверяет остальное — как QuPath вырезает область скана
и переводит обводку в маску. Небольшие расхождения ожидаемы (доли процента), допуск
заказчик назначит по итогам.

Понадобится: компьютер с Windows, около 1 ГБ места, 5–10 сканов H&E трепанобиоптатов в
формате SVS или NDPI (KFB в QuPath не открывается — конвертировать в SVS) — **те же файлы,
что загружены во вьювер**.

## 1. Установка QuPath 0.5.1 (один раз)

1. Откройте страницу выпуска: https://github.com/qupath/qupath/releases/tag/v0.5.1
   и скачайте `QuPath-v0.5.1-Windows.msi` (около 245 МБ). Если загрузка обрывается —
   повторите: `github.com` с этого компьютера отвечает через раз.
2. Запустите файл и установите QuPath с настройками по умолчанию.

Нужна именно версия 0.5.1: на ней авторы проверяли MarrowQuant 2.0.

## 2. Установка MarrowQuant 2.0 (один раз)

1. Откройте https://github.com/Naveiras-Lab/MarrowQuant2.0/releases/tag/qp-v0.5.1 и скачайте
   четыре файла:
   - `Colour_Deconvolution-3.0.2.jar`
   - `qupath-extension-biop-3.1.0.jar`
   - `qupath-extension-stardist-0.5.0.jar`
   - `Source code (zip)` — в нём скрипты.
2. Распакуйте архив с исходным кодом в любую папку, например `Документы\MarrowQuant`.
3. Запустите QuPath и перетащите три файла `.jar` мышью прямо в окно QuPath.
   При первом расширении QuPath спросит папку пользователя — согласитесь с предложенной.
4. Закройте и снова откройте QuPath.

## 3. Проект и сканы

1. Создайте пустую папку, например `Документы\Сверка клеточности`.
2. В QuPath: вкладка **Project** → **Create project** → выберите эту папку.
3. **Add images** → **Choose files** → выберите сканы → **Import**.
   На вопрос о типе изображения выберите **Brightfield (H&E)**.
4. Удобно выключить обзор стекла: меню **View** → снять **Show slide overview**,
   и включить заливку контуров: **View** → **Fill annotations**.

## 4. Обводка: ткань, фон, артефакт

MarrowQuant требует три класса контуров. Названия пишутся **точно так**, с учётом регистра:
`Tissue Boundaries`, `BG`, `Artifact`.

Классы добавляются один раз: вкладка **Annotations** → список классов справа →
кнопка **⋮** → **Add class** → ввести название.

Для каждого фрагмента ткани на скане:

1. **Ткань.** Обведите фрагмент инструментом **Brush** или **Wand** (палочка удобнее;
   в **Edit → Preferences** внизу поставьте Wand smoothing = 1.0, Wand sensitivity = 2.0).
   Выберите контур, щёлкните класс `Tissue Boundaries` и нажмите **Set selected**.
   Обводите только костный мозг с костью, без посторонней ткани.
2. **Закрепите контур ткани:** правая кнопка мыши на контуре → **Annotations** → **Lock**.
   Иначе следующие контуры его испортят.
3. **Фон.** Внутри контура ткани нарисуйте небольшой прямоугольник (**Rectangle**) на
   чистом белом месте без ткани и дайте ему класс `BG`. Один на скан.
   (В коде оригинала поправка по фону выключена, но без этого контура он не запускается.)
4. **Артефакт — хотя бы один в каждом фрагменте.** Обведите разрывы, крупные артефакты
   фиксации, кровоизлияния, хрящ и дайте им класс `Artifact`. Если артефактов нет, обведите
   один совсем маленький участок: **без контура «Artifact» оригинал падает с ошибкой**,
   хотя туториал называет его необязательным. Артефакт должен целиком лежать внутри своего
   фрагмента.

### Проверка вложенности

Откройте вкладку **Hierarchy** слева. Правильное дерево выглядит так: `Tissue Boundaries`,
а под ним с отступом — его `Artifact` (и `BG` у того фрагмента, где он нарисован).

- **`Artifact` обязан быть дочерним** у своего фрагмента: скрипт берёт артефакты только
  среди детей контура ткани. Артефакт на одном уровне с тканью для него не существует,
  и расчёт падает с ошибкой, а выгрузка даёт `NaN` во всех строках.
- **`BG` скрипт ищет по всему скану** и вставляет в дерево сам, поэтому формально он
  сработает и вне ткани. Но рисовать его всё равно следует внутри контура ткани, как в
  туториале авторов.
- Если в дереве всё на одном уровне — меню **Objects** → **Resolve hierarchy**: QuPath
  пересоберёт дерево по вложенности. Если контур после этого не встал внутрь, он не
  целиком внутри ткани: удалите и нарисуйте заново.

Частая ошибка: один `Artifact` на все фрагменты. Нужен **минимум один в каждом**
`Tissue Boundaries`; если настоящих артефактов в фрагменте нет, обведите маленький
участок — на результат это почти не влияет, а считаем мы обе программы по одним контурам.

## 5. Выгрузка контуров (для нашего расчёта)

До запуска MarrowQuant, чтобы в файл не попали его результаты:

1. Меню **File** → **Export objects as GeoJSON**.
2. Тип объектов — **Annotations** (только контуры), отметьте **Pretty JSON**,
   оставьте экспорт как **FeatureCollection**.
3. Сохраните файл рядом с проектом, назвав его по **ID скана во вьювере**
   (виден в адресе страницы после `slide=`), например `840a40f2941d.geojson`.
   Исходное имя файла скана в название не пишите: в нём может быть фамилия.

В файле только координаты контуров и названия классов, изображения и данных пациента нет.

## 6. Запуск MarrowQuant

1. Меню **Automate** → **Script editor**.
2. В окне редактора: **File** → **Open** → `MarrowQuant2\MarrowQuant2.0.groovy`
   из распакованного архива.
3. **Run** → **Run** — для открытого скана, или **Run** → **Run for project** — для всех.
   Откроется окно ImageJ — так и должно быть. Расчёт фрагмента идёт от нескольких секунд
   до минуты.
4. Если появилось предупреждение **«'Other' signal area above 25%»** — запомните, для
   какого скана: наша программа тоже его показывает.

Параметры в начале скрипта не меняйте (жир от 300 мкм², округлость 0,3): сверяем с ними.

## 7. Выгрузка результатов MarrowQuant

1. В редакторе скриптов откройте `MarrowQuant2\Export_MarrowQuant2.0_results.groovy`.
2. **Run** → **Run for project**, отметьте сканы.
3. Результат — файл `results\MarrowQuant_Results.txt` в папке проекта. Строка — фрагмент,
   клеточность в столбцах `Hm.Ar/(Hm.Ar+Tt.Ad.Ar)_%_Equation_1` (формула 1) и
   `Hm.Ar/Ma.Ar_%_Equation_2` (формула 2).

## 8. Что передать разработчику

- файлы `<ID скана>.geojson` — по одному на скан;
- `MarrowQuant_Results.txt` — в нём столбец `Image Name` с именем файла скана: **перед
  отправкой замените имена на ID сканов из вьювера** или пришлите таблицу без этого столбца.

Разработчик запускает на сервере наш расчёт по тем же контурам
(`server.manage cellularity <ID> --resolution original --contours <ID>.geojson`) и
сводит обе таблицы: площади частей и клеточность по обеим формулам для каждого фрагмента.

## Если что-то не так

- **Скрипт упал с NullPointerException** — в каком-то фрагменте нет контура `Artifact`
  или на скане нет `BG`, либо они лежат вне контура ткани.
- **Классы не находятся** — проверьте написание: `Tissue Boundaries` с пробелом и
  заглавными буквами, `BG`, `Artifact`.
- **Скан не открывается** — KFB не поддерживается QuPath, нужен SVS или NDPI.
- **Окно ImageJ не закрылось** — его можно закрыть вручную после расчёта.
