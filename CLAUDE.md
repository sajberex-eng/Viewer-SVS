## Что это

Веб-сервис хранения и просмотра сканов Aperio SVS: администратор загружает сканы через браузер, раскладывает по папкам, выдаёт логины и доступ; пользователи только смотрят. Тайл-сервер на FastAPI и OpenSlide, клиент на чистом HTML/JS с OpenSeadragon, без сборки.

Репозиторий: `github.com/sajberex-eng/Viewer-SVS`, публичный, ветка `main`. В него не должны попадать сканы, `data/`, `config.yaml`, `.env` (исключены в `.gitignore`). Push — по правилам из глобального `CLAUDE.md` пользователя (на компьютере `QQQQ1234` разрешены оба токена, обычный `git push` через Git Credential Manager работает; на других компьютерах — только второй токен); `github.com:443` с этого компьютера отвечает нестабильно, push при тайм-ауте повторять.

## Команды

Локальное окружение — `.venv` на Windows, без Docker (как его создать — ниже, «Запуск на новом компьютере»).

```
.venv\Scripts\python.exe -X utf8 -m uvicorn server.main:app --port 8000     # локальный сервер; после правок server/ перезапускать, web/ подхватывается обновлением страницы
.venv\Scripts\python.exe -X utf8 tests\access_test.py                       # права: обязателен после правок access.py, catalog.py и маршрутов
.venv\Scripts\python.exe -X utf8 tests\upload_test.py                       # загрузка, форматы, этикетка, таблица цвета
.venv\Scripts\python.exe -X utf8 tests\smoke_test.py                        # тайлы, кэш, вход
.venv\Scripts\python.exe -X utf8 tests\cellularity_test.py                  # клеточность (запускает дочерние процессы)
.venv\Scripts\python.exe -X utf8 tests\desktop_test.py                      # настольная программа
.venv\Scripts\python.exe -X utf8 tests\library_test.py                      # настольная программа: подключённые папки
.venv\Scripts\python.exe -m server.manage add-user <логин> --role admin     # пароль вводит заказчик в терминале
```

Тесты — обычные скрипты без pytest: каждый печатает `[OK]`/`[СБОЙ]` по проверке и итоговую строку; отдельной проверки нет, запускается файл целиком. Серверные тесты работают на временной базе и временном хранилище, рабочие данные не трогают; синтетический SVS собирает `tests/synthetic_svs.py`.

Клиент — ES-модули без сборки: синтаксис проверять `node --input-type=module --check < web/static/js/<файл>.js`; дубли ключей словаря — `grep -o "^    '[a-zA-Z.]*'" web/static/js/i18n.js | sort | uniq -d` (дубль молча перекрывается первым значением).

**Стенд для проверки в браузере** — `tools/stand.py` (свой `config.yaml`, данные в `%LOCALAPPDATA%\Temp\hcd-stand`, администратор `stand`/`stand-1234`, пользователь `viewer-only`/`stand-1234`, порт 8012): `seed` — шесть синтетических сканов 2048 px в одном случае, `seed-many` — 12 случаев с подпапками и 135 сканами 512 px для каталога, `serve` — запуск. Наполнение и запуск — разными процессами (`TestClient` уже проходит жизненный цикл приложения, uvicorn в том же процессе падает). Для панели браузера Claude Code временно дописать в `.claude/launch.json` конфигурацию `viewer-stand` (запуск `tools/stand.py serve`, порт 8012), после проверки вернуть файл `git checkout -- .claude/launch.json`. Если заказчик держит стенд запущенным сам, подключаться к нему по URL. Что нельзя проверить в панели браузера (анимации, `<dialog>` `close`, настоящая мышь, буфер обмена) — в [docs/journal.md](docs/journal.md).

**Выкладка на рабочий сервер** (`ssh viewer-svs`; адрес и состояние сервера — в приватной памяти Claude, не здесь): копия базы `systemctl start viewer-backup.service`, копия кода `tar czf /opt/backups/code-before-<коммит>.tgz --exclude=.git --exclude=data .` в `/opt/viewer-svs`, затем код архивом `git archive --format=tar.gz -o <файл> <коммит>` → `scp` в `/tmp/viewer.tar.gz` → `tar xzf` поверх (удалённые из репозитория файлы стирать руками), `nohup docker compose up -d --build > /opt/backups/deploy-<коммит>.log 2>&1 < /dev/null &`, ждать `docker compose ps` со статусом «Up N seconds» (не «minutes» — это старый контейнер), проверить журнал («Хранилище проверено»), `PRAGMA user_version` и счётчики таблиц. `curl` с `api.github.com` на сервере бывает очень медленным — архив по `scp` надёжнее. Многострочные команды на сервер — Bash-инструментом (`ssh viewer-svs 'bash -s' <<'EOF'`), PowerShell 5.1 теряет кавычки; `docker compose exec -T … < /dev/null`, иначе остаток heredoc съедается.

**Push** — по правилам глобального `CLAUDE.md`: на `QQQQ1234` обычный `git push` (первый токен через Git Credential Manager) или второй токен `github-temp-token` (права `repo, workflow, admin:org`); на других компьютерах только второй. `github.com:443` отвечает через раз — повторять.

## Запуск на новом компьютере

Папки `.venv` и `data/cache` с собой не переносить: окружение привязано к путям, кэш пересоздаётся. `data/viewer.sqlite3` хранит пользователей и каталог; без него нужно создать пользователя заново.

```
winget install --id Python.Python.3.12 -e --source winget --scope user
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

В `config.yaml` поправить `storage.root` на папку со сканами на этом компьютере. Пользователь создаётся командой `.venv\Scripts\python.exe -m server.manage add-user <логин> --role admin` (пароль запрашивается в терминале, заказчик вводит его сам). Сервер: `.venv\Scripts\python.exe -m uvicorn server.main:app --port 8000` или конфигурация `viewer` из `.claude/launch.json` для панели браузера.

Запуск без `--reload`: после правки файлов `server/` сервер нужно перезапустить. Файлы `web/` подхватываются обновлением страницы.

## Двухэкранный режим (раздел 8 ТЗ)

Вьювер разделён: `slide-view.js` это одна половина экрана (изображение, увеличения, мини-карта, линейка, этикетка), `viewer.js` управляет одной или двумя половинами, активной половиной, связью и ссылкой. Разметка половины лежит в `<template id="paneTemplate">`, элементы внутри ищутся по `data-role`, а не по `id`: половин бывает две.

- Панель настройки изображения одна на странице, `AdjustPanel.attachTo()` переключает её на активную половину. Значения берутся из `localStorage` по ключу половины.
- Связь (С-6, С-7): положение запоминается относительным в микрометрах в момент связывания, увеличение уравнивается в микроскопических единицах. Синхронизация идёт **без анимации** (`immediately = true`), иначе вторая половина догоняет первую рывками.
- `viewport.resize()` принимает РАЗМЕР, а не флаг: вызов `resize(true)` ломает пересчёт зума и даёт `NaN` в увеличении. Размер контейнера OpenSeadragon отслеживает сам (`autoResize`), поэтому после смены ширины достаточно `forceRedraw()` на следующем кадре.
- Панель увеличений одна на весь экран (`viewer.js`, `initZoomPanel`) и действует сразу на обе половины: сравнивать сканы имеет смысл только в одинаковом масштабе. Текущее увеличение каждой половины показано в её заголовке. Решение заказчика от 2026-09-19.
- В панели браузера Claude Code анимации не проигрываются (нет кадров в фоне), поэтому кнопки увеличений и связь там «не работают». Проверять надо прямыми вызовами с `immediately = true` либо на переднем плане вкладки.
- При проверке кнопок увеличения легко обмануться: значение ниже «вписать» (Fit) ограничивается до Fit, и кажется, что кнопка не сработала. У скана 2048 px в половине шириной 650 Fit это уже 16×, поэтому кнопки 2×, 4× и 10× ничего не меняют — это правильное поведение (Н-1), а не ошибка.
- Мини-карте нужны явные `navigatorWidth`/`navigatorHeight` и `navigatorAutoResize: false`: иначе OpenSeadragon растит её от ширины окна, и в режиме сравнения она закрывает соседнюю половину.
- Статика отдаётся с `Cache-Control: no-cache` (`FreshStatic` в `main.py`): иначе после обновления сервиса браузеры продолжают выполнять старые скрипты. ES-модули кэшируются отдельно от обычных запросов, `fetch(..., {cache:'reload'})` их не обновляет.

## Что важно знать о коде

- `server/tiles.py` заменяет `openslide.deepzoom.DeepZoomGenerator`. У Aperio шаг уровней 4,0001 вместо 4, и стандартный генератор читал полное разрешение: 190 мс на тайл вместо 15–30 мс. Не возвращать стандартный генератор.
- Коррекции изображения: OpenSeadragon работает с `drawer: 'canvas'`, а `web/static/js/adjust.js` после каждого кадра (событие `update-viewport`) копирует этот canvas в текстуру и рисует шейдером на WebGL-canvas поверх. Поэтому не переключать drawer на `webgl`. Порядок коррекций закреплён в ТЗ (И-5, раздел 7.3), формулы описаны в README; та же цепочка на JS — `applyValues` в `adjust.js` (прежний шейдер сверялся с расчётом на JS с расхождением 0; после добавления чёрной и белой точек в этапе 12 сверка по точкам не повторялась — в панели браузера холст WebGL читается пустым).
- Клавиатуру OpenSeadragon отключает обработчик `canvas-key`; все горячие клавиши в `initHotkeys` по `event.code`, чтобы работали в русской раскладке.
- Ключ слайда живёт только на сервере. В API уходят `id` (случайные 12 символов) и `title` из `slide_title()`. Исходное имя файла отдаётся только администратору. При добавлении полей в ответы API проверять, что имя файла туда не попало; это проверяет `access_test.py`.
- Окружение `.venv` привязано к путям: папка проекта была перенесена с другого компьютера, и окружение пришлось пересоздать (`python -m venv .venv` поверх). Если импорты вдруг перестанут работать, начинать с этого.
- Пароли: `bcrypt` напрямую. `passlib` несовместим с bcrypt 5, не добавлять.
- Строки интерфейса только через словарь `web/static/js/i18n.js` (ТЗ требует возможность казахского и английского).
- Панель браузера в Claude Code в фоне даёт около 2 кадров в секунду и пустой `event.code` у нажатий клавиш. Изображение дорисовывается с задержкой, горячие клавиши проверять через `dispatchEvent` с заполненным `code`. Это особенность среды, а не ошибка вьювера. Если OpenSeadragon показывает пустое поле (`lastDrawn: 0`, событий `tile-loaded` нет) при успешных запросах тайлов, вкладка просто не на переднем плане: `tabs_select` и повторный снимок всё показывают.
- Настройки изображения хранит сама половина экрана (`SlideView.adjustValues`, `setAdjust`); общая `AdjustPanel` только показывает и меняет значения активной половины (`attachTo(pane)`). Настройки из ссылки ставятся с `save: false`: у получателя они не записываются в браузер.
- Ссылка на два скана: сведения об обоих сканах запрашиваются до создания половин, иначе первая успевает открыться на весь экран и остаётся с вдвое большим увеличением. Половина при открытии сама сверяет размер области просмотра и вписывает изображение.
- Время в базе — UTC от `CURRENT_TIMESTAMP` без пояса. Наружу оно уходит через `db.utc_iso()` с отметкой `Z`, страница показывает его через `formatDateTime` из `i18n.js`. Новые поля со временем отдавать так же.
- Коды ошибок загрузки несут смысл для страницы (`UploadError(message, status)`): 409 — сверить принятое через `POST /api/uploads` и продолжать; 0, 5xx, 408, 429 — ждать связь (пауза 3 с → 1 мин, событие `online` будит сразу); 400, 401, 403, 404 — остановиться с ошибкой и кнопкой «Повторить». Запросы загрузки идут своей функцией `request()` в `upload.js`, а не через `api()`: истёкшая сессия не должна уводить со страницы посреди загрузки.
- Проверка в браузере без рабочих данных: временный стенд в папке сессии — свой `config.yaml` с `data_dir` и `storage.root` во временной папке, администратор и синтетические сканы (`tests/synthetic_svs.py`) заводятся через API, сервер запускается с `VIEWER_CONFIG`. Панель браузера берёт `launch.json` из папки проекта (до 2026-09-20 брала из корня `GrowVibeProjects`); как поднять стенд — в разделе «Команды». Страница не может обращаться к другим портам (CSP `default-src 'self'`), поэтому тестовый файл для загрузки отдаётся самим стендом и удаляется после проверки. Список загрузок при ширине меньше 700 точек скрыт (М-5): для проверки загрузки расширять окно.
- При удалении файлов из `data/cache` инструмент PowerShell может отказать («protected path»). Кэш не мешает: пространство имён тайлов включает размер и дату файла и параметры нарезки.
