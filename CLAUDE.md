# Веб-вьювер гистосканов: контекст для Claude Code

Этот файл переносится вместе с папкой проекта и заменяет историю переписки. Перед работой прочитай его, затем [PRD.md](PRD.md) (техническое задание, редакция 4; план работ — раздел 13) и [README.md](README.md) (устройство, запуск, развёртывание; соответствует коду).

С заказчиком общаемся по-русски. Заказчик не разработчик: команды и шаги давай готовыми, без предположения, что установлены git, Docker или Node.

## Что это

Веб-сервис хранения и просмотра сканов Aperio SVS: администратор загружает сканы через браузер, раскладывает по папкам, выдаёт логины и доступ; пользователи только смотрят. Тайл-сервер на FastAPI и OpenSlide, клиент на чистом HTML/JS с OpenSeadragon, без сборки.

Репозиторий: `github.com/sajberex-eng/Viewer-SVS`, публичный, ветка `main`. В него не должны попадать сканы, `data/`, `config.yaml`, `.env` (исключены в `.gitignore`). Push только вторым токеном по правилам из глобального `CLAUDE.md` пользователя; `github.com:443` с этого компьютера отвечает нестабильно, push при тайм-ауте повторять.

## Решения заказчика

Редакция 3 (2026-09-19):

- Хостинг: is*hosting (ishosting.com), VPS в Казахстане (Алматы) куплен 2026-09-19: тариф Start, Xeon 2 × 2,60 ГГц, 2 ГБ ОЗУ, диск 30 ГБ SSD (не 40, как заказчик говорил раньше), 1 Гбит/с, 3 ТБ трафика, Ubuntu 24, KVM. Необслуживаемый: без панели и администрирования, без защиты от DDoS, копии провайдера еженедельные, SSH пока по паролю root, VNC не подключён. Под сканы остаётся около 16 ГБ: хранилище это рабочая полка, а не архив. Бюджет диска, меры под 2 ГБ памяти и таблица параметров сервера в разделе 4 ТЗ. Адрес сервера и учётные данные в репозиторий не записывать: он публичный.
- Сканы загружает администратор через веб-интерфейс, частями, с докачкой. Принимаемый файл пишется сразу на место и переименовывается, без второй копии.
- Папки и подпапки создаёт администратор; в названиях нет ФИО. Дерево папок живёт в базе, файлы на диске под внутренними ID.
- Две роли: администратор и пользователь (только просмотр). Логины и пароли выдаёт администратор в веб-интерфейсе.
- Доступ к папке или скану: только администраторы, все пользователи, выбранные пользователи; наследуется от папки, свой режим заменяет унаследованный. Проверка на сервере для сведений, тайлов и миниатюр.
- Файлы загружаются как есть, с этикетками. Заказчик решил: сервер физически в Казахстане, поэтому данные казахстанских пациентов на нём хранить можно. Этикетка (label) показывается во вьювере по кнопке тем, у кого есть доступ к скану; открытие пишется в журнал; отдаётся с `Cache-Control: no-store`. Macro-изображение не отдаётся никому. Не выяснено, где провайдер хранит еженедельные копии VPS.
- Двухэкранный режим (раздел 8 ТЗ): два скана рядом, независимая или связанная навигация с пересчётом в микрометрах, настройки изображения по половинам. Только клиентская часть: два экземпляра OpenSeadragon и два слоя `adjust.js`.
- Домен пока не регистрируется: работаем по IP-адресу сервера, ссылку заказчик рассылает сам. Целевое имя `hemcenterhistodigital.kz`. Сертификат на IP: сначала пробуем Let's Encrypt с профилем `shortlived`, запасной вариант — самоподписанный сертификат Caddy с предупреждением браузера; по HTTP не работаем никогда. Порядок работ: этап 1 сервер, этап 2 хранилище и доступ, этап 3 двухэкранный режим. 16 ГБ под сканы заказчик считает достаточными для тестирования.
- Парольный вход по SSH оставлен включённым и VNC не подключается — решение заказчика, риск принят (за первый день 89 попыток подбора, смягчает fail2ban). Не отключать без его прямого указания.
- Название в интерфейсе: HemCenterHistoDigital. Копии VPS у провайдера хранятся в Казахстане (со слов заказчика). Вход в сервис по логину и паролю, без ограничения по IP. Вход на сервер по SSH-ключам.
- Форматы (2026-09-19): кроме SVS принимаются однофайловые форматы, которые читает OpenSlide (`.ndpi`, `.scn`, `.tiff`, `.tif`, `.bif`, `.czi`, `.avs`, `.svslide`; список `SLIDE_EXTENSIONS` в `storage.py` и `upload.js`). Многофайловые (MRXS, VMS/VMU, DICOM, Trestle) — нет. Файл хранится со своим расширением: NDPI и KFB узнаются по нему.
- KFB (2026-09-19, решение заказчика; риски приняты и записаны в разделе 3 ТЗ): читается через KFB-часть ASlide (GPL-3.0) с закрытой библиотекой KFBio, только Linux. `server/kfb.py` — обёртка под интерфейс OpenSlide, чтение под замком. В образ ставит `tools/install_aslide_kfb.py`: коммит и SHA-256 файлов закреплены, файлы качаются с `raw.githubusercontent.com` (лимита API нет), создаётся ссылка `libcurl.so.4`. Этикетку читать только своим кодом (`_AssociatedImages`): ASlide освобождает чужой буфер, и второе чтение роняет процесс. На Windows KFB недоступен — проверять в образе: `docker build`, файл монтировать `:ro`. Проверено на настоящем скане заказчика (в отчётах — только по ID, файл не копировать).
- Деидентификация и утилита для неё исключены. Каталог случаев с диагнозом и «слепым» режимом исключён.

Действуют по-прежнему:

- Исходные имена файлов не отображаются пользователям, не попадают в пути, адреса, ответы сервера пользователям и журнал сервера. В редакции 3 исходное имя хранится в базе и видно только администратору.
- Клиент без сборки и без Node. Локальная разработка на Windows в `.venv`, без Docker. Файлы Docker пишутся для VPS.
- Тестовые сканы заказчика содержат фамилии в именах части файлов и label-изображения. Их можно только читать локально. Не копировать, не загружать куда-либо (тем более в публичный репозиторий), не называть по имени файла в отчётах: только по ID слайда.

## Этап 2: что уже сделано в коде (2026-09-19)

Серверная часть фундамента готова и покрыта тестами; интерфейс к ней приведён (список ниже).

- `db.py`: схема версионируется через `PRAGMA user_version`, версия 1. Таблицы `folders`, `access_grants`, `audit_log`, расширенные `users` и `slides`. Миграция с базы редакции 2 автоматическая.
- `access.py`: `AccessIndex` — режим доступа папки или скана, наследование, видимость папок. Свой режим заменяет унаследованный; разрешения действуют там же, где задан режим.
- `catalog.py`: дерево папок, карточки сканов, права, проверка целостности хранилища.
- `storage.py`: адаптер умеет сохранять, удалять и считать свободное место; файлы под внутренними ID (`ab/ab12cd34ef56.svs`), имя файла в путь не попадает.
- `auth.py`: роли `user` и `admin`, состояние записи, срок действия, обязательная смена выданного пароля, `session_epoch` (блокировка и смена пароля рвут сессии сразу).
- `audit.py`: журнал действий, переживает удаление пользователя.
- `main.py`: право проверяется на каждый запрос — сведения, тайл, миниатюра, этикетка. Чужой скан отвечает 404, как несуществующий.
- `groups.py`: группы пользователей. При создании базы заводятся «Патологи», «Гематологи», «Резиденты»; администратор создаёт свои. «Администраторы» в таблице нет: это роль `admin`, доступ у неё есть всегда, название зарезервировано. Право пользователя — объединение его прямых разрешений и разрешений всех его групп.
- `uploads.py`: приём файла частями по 8 МБ в один временный файл, докачка с последней принятой части, контрольная сумма каждой части, проверка свободного места с учётом очереди. Готовый файл переносится в хранилище через `os.replace`, без копирования: скан 3 ГБ не занимает 6 ГБ. Файл, который не открывается через OpenSlide, удаляется и в каталог не попадает.
- Тесты: `tests/access_test.py` (69 проверок прав и групп), `tests/upload_test.py` (65 проверок загрузки, форматов и этикетки), `tests/smoke_test.py` (19). Первые два работают на временной базе и временном хранилище, рабочие данные не трогают. `tests/synthetic_svs.py` собирает настоящий минимальный SVS (тайловый TIFF с описанием Aperio), поэтому тесты не зависят от сканов заказчика.

**С сервера и с компьютера заказчика `github.com` не открывается** (таймаут), а `api.github.com` работает. Поэтому `git clone` на сервере не проходит: код переносится архивом `curl -L https://api.github.com/repos/sajberex-eng/Viewer-SVS/tarball/main`, распаковывается с `--strip-components=1`, `config.yaml` и `.env` при этом не трогаются. Push с компьютера заказчика идёт через раз: повторять.

**Caddy по IP-адресу.** Клиент не отправляет имя сервера (SNI), поэтому в `Caddyfile` обязателен глобальный `default_sni {$VIEWER_HOST}`: без него Caddy обрывает соединение и curl показывает пустой ответ. `VIEWER_TLS=internal` даёт самоподписанный сертификат с SAN на IP; Windows-curl такое соединение не открывает («SNI is not supported by OS»), браузер открывает после подтверждения исключения.

Обязательной смены выданного пароля нет (решение заказчика 2026-09-19): колонка `must_change_password` удалена в схеме версии 3. Пользователь меняет пароль сам в профиле; смена обрывает прочие его сессии.

Интерфейс приведён к новому API и проверен в браузере:

- `catalog.js` — дерево папок, путь, поиск, карточки сканов; у администратора создание, переименование, перемещение и удаление папок и сканов, окно «Доступ», свободное место;
- `upload.js` — загрузка перетаскиванием и кнопкой, по два файла сразу, части по 8 МБ с контрольной суммой, докачка после обрыва, отмена, индикатор скорости;
- `dialog.js` — окна на `<dialog>`: ввод, подтверждение необратимых действий, списки отметок, показ выданного пароля;
- `admin.js` и `web/pages/admin.html` (маршрут `/admin`) — вкладки «Пользователи», «Группы», «Журнал» с выгрузкой в CSV;
- панель этикетки во вьювере: изображение запрашивается только по нажатию, поворот на 90°, кнопка неактивна, если этикетки в файле нет.

Проверено вживую на временной базе: загрузка скана через браузер, появление карточки, выдача доступа группе, дерево, вьювер с тайлами.

Локальная база очищена от сканов по решению заказчика: всё загружается через веб-интерфейс. `storage.root` теперь `./data/slides`, папкой управляет только приложение.

### С чего начинать следующую сессию

**Этап 6 (загрузка без повторного выбора файла), пункт ЗГ-6 — раздел 13.3 ТЗ.** Порядок работы прежний: каждый пункт проверять в браузере на временном стенде, после этапа три набора тестов и сверка с критериями приёмки по одному; коммит, пуш и деплой — только после подтверждения заказчика, деплой одним выпуском после всего этапа.

Этап 5 сделан 2026-09-20 и проверен на временном стенде, но **не закоммичен и не выложен**: ждёт подтверждения заказчика. Что сделано:

- `server/warmup.py` (СК-1) — после приёма файла один фоновый поток готовит миниатюру и тайлы всех уровней, где тайлов не больше 100. Пауза 20 мс между тайлами, чтобы не занимать ядро целиком. Прогрев ставится в очередь в обработчике `complete_upload`, сбой прогрева на загрузку не влияет. Ранее загруженные сканы: `python -m server.manage warm` (повторный запуск дёшев — готовые тайлы пропускаются).
- `server/perms.py` + подключение к базе на поток в `db.py` (СК-3) — учётная запись и `AccessIndex` живут в памяти процесса. Сбрасывает их middleware `drop_permission_cache` после любого запроса, кроме GET/HEAD и `/api/uploads*` (части файла идут по нескольку раз в секунду и на права не влияют). Срок годности 3 с — на случай правки базы командой `server.manage` в другом процессе. Сервис работает одним процессом, иначе кэш пришлось бы делать общим.
- СК-4 `immutable` в заголовке тайлов, СК-5 отметка «использован» не чаще раза в час, СК-6 `imageLoaderLimit: 8` (проверено: у половины экрана `jobLimit` 8; у мини-карты свой экземпляр OpenSeadragon, ограничение на него не распространяется — тайлов там единицы).
- Журнал сервера: uvicorn настраивает только свои журналы, поэтому `log.info` сервиса никуда не попадал. Теперь `create_app` настраивает корневой журнал, если его никто не настроил. Без этого прогрев не видно в журнале.
- Прогрев на KFB не проверен: на Windows KFB не читается, проверять надо в образе Docker на сервере.

**Оставшийся замер СК-2** (нужен ли прогрев промежуточных уровней) делается на рабочем сервере после выкладки, на настоящих сканах.

Репозиторий пока публичный; заказчик сделает его закрытым позже, когда проект будет доработан (решение 2026-09-19, в том числе из-за GPL-зависимости ASlide). До тех пор правила прежние: ни адреса сервера, ни сканов, ни имён файлов заказчика в репозитории.

Решения заказчика получены 2026-09-19: ставят только участники группы «Патологи» (клетка или участок с комментарием), остальные с доступом к скану видят; пометки не должны мешать просмотру — маленькие маркеры, комментарий по наведению; любой пользователь выключает и включает показ кнопкой (А-11); личные пометки желательны, но не обязательны (А-13).
10. Желательные доработки: общий курсор, импорт SFTP, двухфакторный вход, S3, домен.

После каждого этапа: три набора тестов, проверка в браузере, коммит, развёртывание. Версия статики считается при старте сервера — после правки скриптов и стилей локальный сервер перезапускать.

## Запуск на новом компьютере

Папки `.venv` и `data/cache` с собой не переносить: окружение привязано к путям, кэш пересоздаётся. `data/viewer.sqlite3` хранит пользователей и каталог; без него нужно создать пользователя заново.

```
winget install --id Python.Python.3.12 -e --source winget --scope user
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

В `config.yaml` поправить `storage.root` на папку со сканами на этом компьютере. Пользователь создаётся командой `.venv\Scripts\python.exe -m server.manage add-user <логин> --role admin` (пароль запрашивается в терминале, заказчик вводит его сам). Сервер: `.venv\Scripts\python.exe -m uvicorn server.main:app --port 8000` или конфигурация `viewer` из `.claude/launch.json` для панели браузера.

Запуск без `--reload`: после правки файлов `server/` сервер нужно перезапустить. Файлы `web/` подхватываются обновлением страницы.

## Двухэкранный режим (раздел 8 ТЗ)

Вьювер разделён: `slide-view.js` это одна половина экрана (изображение, увеличения, мини-карта, линейка, этикетка), `viewer.js` управляет одной или двумя половинами, активной половиной, связью и ссылкой. Разметка половины лежит в `<template id="paneTemplate">`, элементы внутри ищутся по `data-role`, а не по `id`: половин бывает две.

- Панель настройки изображения одна на странице, `AdjustPanel.attachTo()` переключает её на активную половину. Значения берутся из `localStorage` по ключу половины.
- Связь (С-6, С-7): положение запоминается относительным в микрометрах в момент связывания, увеличение уравнивается в микроскопических единицах. Синхронизация идёт **без анимации** (`immediately = true`), иначе вторая половина догоняет первую рывками.
- `viewport.resize()` принимает РАЗМЕР, а не флаг: вызов `resize(true)` ломает пересчёт зума и даёт `NaN` в увеличении. Размер контейнера OpenSeadragon отслеживает сам (`autoResize`), поэтому после смены ширины достаточно `forceRedraw()` на следующем кадре.
- Панель увеличений одна на весь экран (`viewer.js`, `initZoomPanel`) и действует сразу на обе половины: сравнивать сканы имеет смысл только в одинаковом масштабе. Текущее увеличение каждой половины показано в её заголовке. Решение заказчика от 2026-09-19.
- В панели браузера Claude Code анимации не проигрываются (нет кадров в фоне), поэтому кнопки увеличений и связь там «не работают». Проверять надо прямыми вызовами с `immediately = true` либо на переднем плане вкладки.
- При проверке кнопок увеличения легко обмануться: значение ниже «вписать» (Fit) ограничивается до Fit, и кажется, что кнопка не сработала. У скана 2048 px в половине шириной 650 Fit это уже 16×, поэтому кнопки 2×, 4× и 10× ничего не меняют — это правильное поведение (Н-1), а не ошибка.
- Мини-карте нужны явные `navigatorWidth`/`navigatorHeight` и `navigatorAutoResize: false`: иначе OpenSeadragon растит её от ширины окна, и в режиме сравнения она закрывает соседнюю половину.
- Статика отдаётся с `Cache-Control: no-cache` (`FreshStatic` в `main.py`): иначе после обновления сервиса браузеры продолжают выполнять старые скрипты. ES-модули кэшируются отдельно от обычных запросов, `fetch(..., {cache:'reload'})` их не обновляет.

## Что важно знать о коде

- `server/tiles.py` заменяет `openslide.deepzoom.DeepZoomGenerator`. У Aperio шаг уровней 4,0001 вместо 4, и стандартный генератор читал полное разрешение: 190 мс на тайл вместо 15–30 мс. Не возвращать стандартный генератор.
- Коррекции изображения: OpenSeadragon работает с `drawer: 'canvas'`, а `web/static/js/adjust.js` после каждого кадра (событие `update-viewport`) копирует этот canvas в текстуру и рисует шейдером на WebGL-canvas поверх. Поэтому не переключать drawer на `webgl`. Порядок коррекций закреплён в ТЗ (И-5), формулы описаны в README; шейдер сверен с расчётом на JS, расхождение 0.
- Клавиатуру OpenSeadragon отключает обработчик `canvas-key`; все горячие клавиши в `initHotkeys` по `event.code`, чтобы работали в русской раскладке.
- Ключ слайда живёт только на сервере. В API уходят `id` (случайные 12 символов) и `title` из `slide_title()`. Исходное имя файла отдаётся только администратору. При добавлении полей в ответы API проверять, что имя файла туда не попало; это проверяет `access_test.py`.
- Окружение `.venv` привязано к путям: папка проекта была перенесена с другого компьютера, и окружение пришлось пересоздать (`python -m venv .venv` поверх). Если импорты вдруг перестанут работать, начинать с этого.
- Пароли: `bcrypt` напрямую. `passlib` несовместим с bcrypt 5, не добавлять.
- Строки интерфейса только через словарь `web/static/js/i18n.js` (ТЗ требует возможность казахского и английского).
- Панель браузера в Claude Code в фоне даёт около 2 кадров в секунду и пустой `event.code` у нажатий клавиш. Изображение дорисовывается с задержкой, горячие клавиши проверять через `dispatchEvent` с заполненным `code`. Это особенность среды, а не ошибка вьювера. Если OpenSeadragon показывает пустое поле (`lastDrawn: 0`, событий `tile-loaded` нет) при успешных запросах тайлов, вкладка просто не на переднем плане: `tabs_select` и повторный снимок всё показывают.
- Настройки изображения хранит сама половина экрана (`SlideView.adjustValues`, `setAdjust`); общая `AdjustPanel` только показывает и меняет значения активной половины (`attachTo(pane)`). Настройки из ссылки ставятся с `save: false`: у получателя они не записываются в браузер.
- Ссылка на два скана: сведения об обоих сканах запрашиваются до создания половин, иначе первая успевает открыться на весь экран и остаётся с вдвое большим увеличением. Половина при открытии сама сверяет размер области просмотра и вписывает изображение.
- Время в базе — UTC от `CURRENT_TIMESTAMP` без пояса. Наружу оно уходит через `db.utc_iso()` с отметкой `Z`, страница показывает его через `formatDateTime` из `i18n.js`. Новые поля со временем отдавать так же.
- Коды ошибок загрузки несут смысл для страницы (`UploadError(message, status)`): 409 — сверить принятое через `POST /api/uploads` и продолжать; 0, 5xx, 408, 429 — ждать связь (пауза 3 с → 1 мин, событие `online` будит сразу); 400, 401, 403, 404 — остановиться с ошибкой и кнопкой «Повторить». Запросы загрузки идут своей функцией `request()` в `upload.js`, а не через `api()`: истёкшая сессия не должна уводить со страницы посреди загрузки.
- Проверка в браузере без рабочих данных: временный стенд в папке сессии — свой `config.yaml` с `data_dir` и `storage.root` во временной папке, администратор и синтетические сканы (`tests/synthetic_svs.py`) заводятся через API, сервер запускается с `VIEWER_CONFIG`. Панель браузера берёт `launch.json` из корня `GrowVibeProjects`, а не из папки проекта. Страница не может обращаться к другим портам (CSP `default-src 'self'`), поэтому тестовый файл для загрузки отдаётся самим стендом и удаляется после проверки. Список загрузок при ширине меньше 700 точек скрыт (М-5): для проверки загрузки расширять окно.
- При удалении файлов из `data/cache` инструмент PowerShell может отказать («protected path»). Кэш не мешает: пространство имён тайлов включает размер и дату файла и параметры нарезки.
